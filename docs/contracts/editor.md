# Editor behaviour contract

This file lists the observable rules of the editor kit's document engine
(`kits/editor/`) and of the two applications it will replace the text
engines of: Editor (`apps/editor/`) and the BASIC/C IDE (`apps/ide/`).

Each row is one rule a test can check. Rows for the applications record how
they behave today, so a migration can be checked against them. Where a
migration will change a rule on purpose, the change is listed under
[Decisions](#decisions) before it is made.

## Reading the rows

| Column | Meaning |
| --- | --- |
| ID | Stable name. Tests print it when a check fails |
| Source | Where the rule comes from: Tiku policy, a Scintilla file, or the application's code today |
| Rule | The behaviour, in one sentence |
| State | `done`: implemented, and the named test passes. `baseline`: how the application behaves now, first recorded at `bf1c6b3`; a migration keeps it unless a decision says otherwise. `open`: a difference or defect waiting for a decision |
| Test | The test that checks it, as `file:function`, or `none` |

Engine tests are in `tests/kits/`, application tests in `tests/apps/`, and
shell scripts in `tests/integration/shell/`. Upstream Scintilla cases
translated into the engine tests are listed in `kits/editor/UPSTREAM.md`,
not here.

## Decisions

These are settled for the engine. The migration rows they affect are marked
`open` until the migration that meets them.

1. **An edit may split or join a CRLF pair.** The engine accepts a
   replacement that ends between a CR and its LF, or one that places a CR
   before an existing LF, and keeps the line index right in both cases
   (LINES-CRLF). Only a selection must sit at a caret position, never between
   a CR and its LF (MRK-007, MRK-008).
2. **Text is valid UTF-8 without NUL.** Tabs, CR, other control characters
   and DEL are ordinary text. Unicode noncharacters are accepted. The
   engine does not refuse mixed line endings. Today Editor refuses control
   characters other than tab and LF, and refuses a bare CR and mixed
   endings (EDR-FILE-008, EDR-FILE-009, EDR-UNDO-008). The IDE keeps CR and
   mixed endings, refuses other control bytes when loading (IDE-FILE-001) and
   drops them on paste (IDE-CLIP-003). Each application keeps or drops its
   own refusals at its migration; the engine does not impose them.
3. **Undo restores the selection the view had before the step.** Redo
   restores the selection after it. Today Editor puts the caret at the end of
   the restored text (EDR-UNDO-005), and the text view puts it at the start
   of an undone insertion or after an undone deletion (TXV-022). Which rule
   each application shows is decided at its migration; the application can
   set its own selection after an undo.
4. **Typing joins into one undo step.** A transaction flagged as typing, of
   one replacement, from the same view, joins the previous step. Insertions
   join when they continue where the last one ended. Backspace and Delete
   presses join when they continue the last deletion. A step ends at a save,
   at undo or redo, at a load, when the view's selection is set, when a
   non-typing edit arrives, or when the application seals it, for example
   after an idle interval. Today Editor records every key as its own step
   and keeps at most 256 steps (EDR-UNDO-001, EDR-UNDO-002); it takes this
   rule when it moves onto the engine.
5. **History is bounded by bytes, not by a step count.** The default budget
   is 32 MiB per document. Whole oldest steps are dropped, and the newest
   step is kept even when it alone is larger. The text view's 256-entry cap
   (TXV-023) stays with the text view.
6. **Applications keep their own limits.** The engine's size limit
   (1 GiB by default) is a document setting. Input staging, the clipboard,
   board uploads and the IDE's line limits are the applications' rules and
   are recorded in their rows.

## Editor today

Editor as it behaves now, each row checked against the code at `bf1c6b3`
and updated as fixes land.
Paths are shortened: `editor/` is `apps/editor/`, a bare `tiku_*.c` file is
in `kits/interface/`, and `shell/X.script` is
`tests/integration/shell/X.script`. A test followed by a note in brackets
covers only that part of the rule. A row is `open` when a decision above
changes it or when it records a defect listed under
[Known defects](#known-defects).

## Baseline fixtures

Three tests run generated fixtures through the document engine, through
Editor's own file loader and buffer, and through the IDE's own page
loader and text view:

```sh
make build/tests/test_editdoc_fixtures build/tests/test_editor_baseline \
     build/tests/test_ide_baseline
./build/tests/test_editdoc_fixtures
./build/tests/test_editor_baseline
./build/tests/test_ide_baseline
```

`TIKU_EDITOR_STRESS=1` adds the 100 MiB fixture. `TIKU_EDITOR_FIXTURES=<dir>`
keeps the generated files in that folder so they can be opened by hand.
The generator is `tests/fixtures/editor_fixtures.inc`; nothing large is
committed.

Each implementation that opens a fixture runs the same script, and its
text is compared with a plain model after the script, after undo and
after redo:

1. 100 typed characters, alternating between the start of the first line
   and the start of the last line. This moves the engine's gap across the
   whole text every time, so it is the engine's worst case.
2. 50 line breaks typed in the middle of the middle line.
3. One replacement of the middle half of the document by generated lines,
   then undo and redo. In the CRLF fixture the replacement runs from inside
   line 1 to inside line 3, across two CRLF pairs.

The tests assert which fixtures each application opens or refuses, and
with which message, so a change to either fails them. Timings are printed
and never asserted. These are document-level costs. Frame latency needs
the widget, and is measured there.

### Costs

The three tests also print, for each fixture an implementation opens, the
time to load it, the heap it adds, the time to copy the whole text, the
median and 95th percentile of each typed character and line break, and the
time of the replacement, its undo and its redo. They depend on the machine,
so they are recorded with the machine they come from rather than here.
