# Editor behaviour contract

This file lists the observable rules of the editor kit's document engine
and code view (`kits/editor/`) and of the two applications whose text
engines it replaced: Editor (`apps/editor/`) and the BASIC/C IDE
(`apps/ide/`).

Each row is one rule a test can check. Rows for the applications record how
they behave today, so a migration can be checked against them. Where a
migration will change a rule on purpose, the change is listed under
[Decisions](#decisions) before it is made.

## Reading the rows

| Column | Meaning |
| --- | --- |
| ID | Stable name. Tests print it when a check fails |
| Source | Where the rule comes from: Tiku policy, a Scintilla file, or the application's code today |
| Rule | The behaviour, in one sentence |
| State | `done`: implemented, and the named test passes. `baseline`: how the application behaves now, first recorded at `bf1c6b3`; a migration keeps it unless a decision says otherwise. `open`: a difference or defect waiting for a decision |
| Test | The test that checks it, as `file:function`, or `none` |

Kit tests are in `tests/kits/`, application tests in `tests/apps/`, and
shell scripts in `tests/integration/shell/`. Upstream Scintilla cases
translated into the engine tests are listed in `kits/editor/UPSTREAM.md`,
not here.

## Decisions

These are settled for the engine. The migration rows they affect are marked
`open` until the migration that meets them.

1. **An edit may split or join a CRLF pair.** The engine accepts a
   replacement that ends between a CR and its LF, or one that places a CR
   before an existing LF, and keeps the line index right in both cases
   (LINES-CRLF). Only a selection must sit at a caret position, never between
   a CR and its LF (MRK-007, MRK-008).
2. **Text is valid UTF-8 without NUL.** Tabs, CR, other control characters
   and DEL are ordinary text. Unicode noncharacters are accepted. The
   engine does not refuse mixed line endings. Neither Editor (decision 7)
   nor the IDE (decision 10) refuses any of these.
3. **Undo restores the selection the view had before the step.** Redo
   restores the selection after it. Editor (EDR-UNDO-005) and the IDE
   (decision 11) show this rule. The text view puts the caret at the start
   of an undone insertion or after an undone deletion (TXV-022), and an
   application can set its own selection after an undo.
4. **Typing joins into one undo step.** A transaction flagged as typing, of
   one replacement, from the same view, joins the previous step. Insertions
   join when they continue where the last one ended. Backspace and Delete
   presses join when they continue the last deletion. A step ends at a save,
   at undo or redo, at a load, when the view's selection is set, when a
   non-typing edit arrives, or when the application seals it, for example
   after an idle interval. Editor follows this rule (EDR-UNDO-001).
5. **History is bounded by bytes, not by a step count.** The default budget
   is 32 MiB per document. Whole oldest steps are dropped, and the newest
   step is kept even when it alone is larger. Editor follows this rule
   (EDR-UNDO-002); the text view's 256-entry cap (TXV-023) stays with the
   text view.
6. **Applications keep their own limits.** The engine's size limit
   (1 GiB by default) is a document setting. Input staging, the clipboard,
   board uploads and the IDE's line limits are the applications' rules and
   are recorded in their rows.
7. **Editor keeps a file's bytes.** On the engine, Editor loads LF, CRLF,
   lone CR and mixed line endings, and control characters other than NUL,
   and saves every byte back as it was. A NUL still marks a binary file and
   malformed UTF-8 is still refused. Return types the line break the file
   uses most, the one it uses first when two are as common, and LF in a file
   with none (EDR-FILE-008, EDR-FILE-009, EDR-KEY-003).
8. **Editor's clipboard carries LF.** Copy and Cut give the clipboard "\n"
   for every line break, whatever the document uses, and Paste turns each
   CRLF, CR or LF it brings into the document's line break. Control
   characters paste as text (EDR-CLIP-001, EDR-CLIP-004, EDR-CLIP-007,
   EDR-UNDO-008).
9. **Editor takes the view's caret rules.** Up and Down keep an x; Left or
   Right over a selection stop at its edge; two and three clicks select a
   word and a line; Option or Cmd with Left or Right move by words; undo
   restores the selection before the step and redo the one after
   (decision 3); Replace All leaves each selection on its text (EDR-KEY-005,
   EDR-SEL-001, EDR-SEL-003, EDR-UNDO-005, EDR-UNDO-012, EDR-FIND-011).
   Decisions 4 and 5 apply to Editor as they stand.
10. **The IDE keeps a file's bytes.** As Editor does (decision 7), a page
    loads LF, CRLF, lone CR and mixed line endings and control characters
    other than NUL, and keeps every byte. A NUL or malformed UTF-8 still
    refuses the load and blocks saving and running. Save writes the bytes as
    they are and ends an unended last line with the file's main line break,
    because both BASIC runners read a program line by line and would join
    RUN onto that line. Return types the main break (IDE-FILE-001,
    IDE-FILE-004, IDE-FILE-005, IDE-KEY-003).
11. **The IDE takes the view's editing rules.** Decisions 3, 4, 5, 8 and 9
    apply to the IDE: typing joins into one undo step, a Return and its line
    number included; history is bounded by 32 MiB; the clipboard carries LF
    and a paste takes the page's line break; the view's caret, pointer,
    tab-stop and control-character rules hold; Cut deletes only what the
    clipboard took; Replace selects the next match and All keeps selections
    on their text. A page has no line or line count limit. Kept from before:
    Tab inserts nothing, BASIC's line numbers and keyword upper-casing, and
    a modifier the view has no move for drops to the plain key
    (IDE-KEY-001 to IDE-KEY-015, IDE-SEL-001, IDE-CLIP-001 to IDE-CLIP-004).
12. **BASIC's limits are checked where a program leaves the page.** A local
    run, a board run, Save on DEVICE and a debug run refuse a program with a
    control character other than tab, CR and LF, a line longer than the 159
    bytes the interpreter reads, or more than the 143 bytes it keeps after a
    line's number, and name the line. The interpreter would otherwise cut
    such a line or act on the character without saying so (IDE-RUN-006).
13. **Breakpoints are line markers.** A breakpoint marks a physical line and
    follows it through edits (LMK rows); Renumber replaces only the digits
    that change, so marks stay on their lines. When debugging starts, each
    marked line must still start with a BASIC number and be the last line
    wearing it, the one the interpreter keeps; that number is sent
    (IDE-DEBUG-001, IDE-DEBUG-003, IDE-NUM-003).
14. **The paused line is marked for the text the run was given.** While a
    debug run holds a page, its document refuses every change. The paused
    line is marked as the document's execution line only while the
    document's history state is the one saved for the run; any change makes
    the mark stale instead of moving it (EXE rows, IDE-DEBUG-005,
    IDE-DEBUG-006).
15. **Completion and keyword help are a list and a tip at the caret.** The
    view's list of keywords under the word and a tip beside it with the
    help and the keys replace the 126-pixel band above the page; the keys,
    presses, words and help are those the band had (IDE-ASSIST-001 to
    IDE-ASSIST-007).
16. **The view edits by lines.** Return keeps the indentation of the line
    it breaks, up to the caret; after a line whose C code ends with "{" it
    opens a level, and a "}" right after the caret goes to a line of its
    own. A "}" typed first on a line takes the indentation of its opener's
    line. Tab over a selection spanning lines indents them, Shift+Tab
    unindents, and Tab at a caret still types a tab. The view adds Toggle
    comment, Duplicate, Move and Delete lines, word deletes and the
    matching bracket, and can mark the bracket by the caret and its match.
    What a comment, a level and a bracket are comes from rules for C,
    BASIC (REM after the line's number) and prose. This replaces "no
    auto-indent" and "Shift with Tab types a tab" in EDR-KEY-003 and
    "Shift with Tab is the application's" in EDT-002; IDE BASIC pages keep
    their own Return (LNC rows, BRC rows, EDR-TEXT rows, IDE-TEXT-001).
17. **A view can wrap its lines.** With the wrap option a line breaks into
    rows at the text's width and keeps every byte; tab stops still count
    from the line's start. The scroll position and the extent down count
    rows, and wrapped text never scrolls across. A caret where a row breaks
    shows at the next row's start, unless End, a press past the row's end
    or a row move left it at the end of the row it ends. Home and End go to
    the row's ends first and then the line's. This qualifies LAY-005,
    LAY-006 and LAY-008 (rows, not lines, while wrapping), NAV-004 and
    DSP-002 (a line numbered on its first row), and Editor's View menu gains
    Wrap Lines (WRP rows, EDR-MENU-001, EDR-VIEW-018).
18. **Editor can split its page.** View > Split Pane shows the document in
    two panes, one above the other, each a view of the one document with
    its own caret, selection, scroll and scrollbar (LAY-009, NAV-011). A
    press in a pane gives it the keys, and the commands and the footer
    follow that pane. Taken again, the pane with the keys stays
    (EDR-SPLIT rows, EDR-MENU-001).
19. **Problems are shown on the text.** A document keeps indicators over
    ranges of text and annotations under lines, each of a kind the
    application gives a meaning to. A view draws a kind's indicators with
    a wavy or straight line or a frame, shows annotations as rows under
    their line that the caret passes over, and goes from one indicator to
    the next. The IDE shows what a run or build says about a line this way,
    in place of the Messages window alone (IND, ANN, IMK, ANV and
    IDE-DIAG rows).
20. **A view folds regions the rules tell.** A line leaving a brace open,
    opening a BASIC block or followed by lines indented further heads a
    region, read from the text each time. Each view folds and unfolds on
    its own: a folded region's lines take no rows, the caret is kept out of
    them, and whatever puts the caret in them unfolds them. An edit shows
    the lines it touched and the folded lines next to it. This qualifies
    DSP-001 and DSP-007 (the fold column), and Editor's Text menu gains the
    fold commands (FLD rows, EDR-FOLD rows).
21. **A view can hold several selections.** The document keeps each view's
    selections in order, those that overlap merged, one of them the main one
    the one-selection calls read. Typing, deleting, Return, Tab and the
    clipboard change every selection as one transaction, and undo gives the
    whole set back; other commands act on the main one and drop the rest. A
    Command press adds a caret, an Option drag selects a rectangle by drawn
    columns, and Escape keeps the main one. This qualifies EDT-001 and
    EDR-KEY-001 (a step with several selections joins no typing) and FLD-005
    (every selection leaves a folded region), and Editor's Text menu gains
    Carets to Line Ends (SEL, CAR and EDR-CARET rows).

## Code view

The kit's widget: a view of a document that lays out, paints, colours and
hit tests its text, moves its caret and selection, edits, searches, and
works with a host's clipboard. Each view keeps its own selection in the
document and its own scroll position. These are kit rules. Editor runs on
the view and follows them (decision 9); the IDE keeps its rules in its own
section until it moves onto the view, and any difference is decided then.

## Baseline fixtures

Three tests run generated fixtures through the document engine, through
Editor's own file loader and the document it loads into, and through the
IDE's own page loader and the page's document:

```sh
make build/tests/test_editdoc_fixtures build/tests/test_editor_baseline \
     build/tests/test_ide_baseline
./build/tests/test_editdoc_fixtures
./build/tests/test_editor_baseline
./build/tests/test_ide_baseline
```

`TIKU_EDITOR_STRESS=1` adds the 100 MiB fixture. `TIKU_EDITOR_FIXTURES=<dir>`
keeps the generated files in that folder so they can be opened by hand.
The generator is `tests/fixtures/editor_fixtures.inc`; nothing large is
committed.

Each implementation that opens a fixture runs the same script, and its
text is compared with a plain model after the script, after undo and
after redo:

1. 100 typed characters, alternating between the start of the first line
   and the start of the last line. This moves the engine's gap across the
   whole text every time, so it is the engine's worst case.
2. 50 line breaks typed in the middle of the middle line.
3. One replacement of the middle half of the document by generated lines,
   then undo and redo. In the CRLF fixture the replacement runs from inside
   line 1 to inside line 3, across two CRLF pairs.

The tests assert which fixtures each application opens or refuses, and
with which message, so a change to either fails them. Timings are printed
and never asserted. These are document-level costs. Frame latency needs
the widget, and is measured there.

### Costs

The three tests also print, for each fixture an implementation opens, the
time to load it, the heap it adds, the time to copy the whole text, the
median and 95th percentile of each typed character and line break, and the
time of the replacement, its undo and its redo. They depend on the machine,
so they are recorded with the machine they come from rather than here.
