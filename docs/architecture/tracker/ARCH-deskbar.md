# Architecture notes — Deskbar: the whole application

Read from the real source; structural facts the rewrite must
reproduce for this area.

THREE LOOPERS + A POLLING THREAD, and they cross-lock constantly.
(1) TBarApp (BServer, sig "application/x-vnd.Be-TSKB", B_EXCLUSIVE_LAUNCH) owns ALL settings (desk_settings fSettings, defaults fDefaultSettings, clock_settings fClockSettings) and the two settings files (~/config/settings/deskbar/{settings,clock_settings}); every view reads settings through static_cast<TBarApp*>(be_app)->Settings(). Settings are written to disk ONLY in TBarApp::SaveSettings() from ~TBarApp/QuitRequested — a crash loses them. TBarApp::InitSettings computes the global metrics sIconGap/gDragWidth/gDragRegionWidth/gMinReplicant{Width,Height}/gMinimumTrayWidth/gMinimumWindowWidth/gMaximumWindowWidth (=2x minimum) BEFORE any view exists; everything else depends on them.
(2) TBarWindow (BWindow, B_BORDERED_WINDOW, B_ALL_WORKSPACES, flags: NOT_CLOSABLE|NOT_MINIMIZABLE|NOT_MOVABLE|NOT_V_RESIZABLE|AVOID_FRONT|WILL_ACCEPT_FIRST_CLICK|ASYNCHRONOUS_CONTROLS) holds TBarView, which owns the whole view tree: TBarMenuBar (leaf title + optional team title/separator) + TDragRegion{TResizeControl, TReplicantTray{TTimeView, TReplicantShelf}} + TInlineScrollView{TExpandoMenuBar}. sDeskbarMenu is a STATIC on TBarWindow set from TBarMenuBar's constructor.
(3) TSwitchManager is a BHandler added to its own TSwitcherWindow looper; TBarApp forwards 'TASK' to it via fSwitcherMessenger. It serializes entry with a semaphore fMainMonitor (count 1): first 'TASK' acquires and runs MainEntry (which BLOCKS its looper up to 180 ms polling modifiers), later ones fail the acquire and call Process(); Stop() releases.
(4) TExpandoMenuBar spawns ONE static low-priority thread (monitor_team_windows) that polls every 150 ms, guarded by static BLocker sMonLocker, and takes Window()->LockWithTimeout(50000) each pass. RemoveTeam takes sMonLocker to stall the poller while it mutates items. Vertical mode starts it, horizontal stops it.

TEAM BOOKKEEPING IS A PUBLISH/SUBSCRIBE FAN-OUT. TBarApp keeps the single truth (static BList sBarTeamInfoList of BarTeamInfo{teams BList, flags, sig, name, icon, iconCache[]}), guarded by static BLocker sSubscriberLock. TBarApp::Subscribe(messenger, list) both COPIES the whole team list into the caller's list and registers the caller; three independent subscribers exist (TExpandoMenuBar, TTeamMenu, TSwitchManager) and each keeps its own copy. AddTeam/RemoveTeam broadcast B_SOME_APP_LAUNCHED / kAddTeam / kRemoveTeam / B_SOME_APP_QUIT to every subscriber. Crucially: kAddTeam/kRemoveTeam mean "another/one-of-several instance of an already-listed signature", B_SOME_APP_LAUNCHED/B_SOME_APP_QUIT mean "first/last instance". Ownership across the message boundary is hand-rolled: the broadcast passes a NEW BList* and a NEW BBitmap* by POINTER ("teams", "icon") and the receiver takes ownership.

PLACEMENT IS ONE PIPELINE, ALWAYS IN THIS ORDER. TBarView::_ChangeState (reached only via ChangeState(), sync or async through kUpdateOrientation) sets fState/fVertical/fLeft/fTop then calls PlaceDeskbarMenu() -> PlaceTray(vertSwap,leftSwap) -> PlaceApplicationBar(); the last calls SizeWindow(screenFrame)+PositionWindow(screenFrame), both of which re-derive geometry from GetPreferredWindowSize(). Any state change also posts kStateChanged to be_app (which forwards to the prefs window) and calls TBarWindow::SetSizeLimits(). Sizing must be idempotent — UpdatePlacement() re-runs the pipeline with unchanged arguments and is called from many places (workspace activated, screen changed, tray grew, width changed).

THREE STATES x ORIENTATION x CORNER: fState in {kMiniState=0, kExpandoState=1, kFullState=2} (kFullState is compiled out — #define FULL_MODE is commented in StatusView.h) crossed with fVertical/fLeft/fTop. Mini = leaf title + team title + tray only (expando hidden). Vertical expando = leaf title on top, tray, then the app list down the side, window width user-resizable between gMinimumWindowWidth and gMaximumWindowWidth. Horizontal expando = leaf title + separator on the left, app list in a row, tray pinned to the screen's right edge, window spans the full screen width. TBarWindow::DeskbarLocation() maps the flags back to the 6 public deskbar_location values.

COORDINATE/OWNERSHIP QUIRKS THE REWRITE MUST REPRODUCE: TBarView installs a window-wide BMessageFilter (BarViewMessageFilter) so it sees B_MOUSE_DOWN/B_MOUSE_MOVED that land on child views, and it reads "screen_where" out of the raw message because `where` is relative to whichever child got the event. TBarView tracks the mouse outside the window (SetEventMask(B_POINTER_EVENTS)) only while auto-raise or auto-hide is on, and clears the mask otherwise. The tray's parent is TDragRegion, so TBarView::OffsetIconFrame composes barView+dragRegion+tray offsets to answer BDeskbar's icon-frame query.

BDESKBAR API SURFACE: TBarApp answers kMsgIsAlwaysOnTop/kMsgIsAutoRaise/kMsgIsAutoHide itself and forwards kMsgLocation/kMsgSetLocation/kMsgIsExpanded/kMsgExpand/kMsgGetItemInfo/kMsgHasItem/kMsgCountItems/kMsgMaxItemSize/kMsgAddView/kMsgRemoveItem/kMsgAddAddOn plus 'iloc' to TBarWindow, which unpacks them into TBarView -> TReplicantTray. Replicant ids come from BShelf; the tray keeps a parallel BList of DeskbarItemInfo{isAddOn,id,entryRef,nodeRef} so it can node-monitor add-on files and persist their paths.

INVARIANTS: only one TWindowMenu per team item, and its items MIGRATE between the submenu and the expando bar on expand/collapse (ToggleExpandState moves CountItems()-4 items — the tail is hide/show/close/separator); a menu item is never in two menus. The tray's fRightBottomReplicant/fLastReplicant are the running max used to size the tray, and are reset only when RealignReplicants starts at index 0. TDeskbarMenu sets fMenuBuilt=false in ClearMenuBuildingState so the leaf menu is rebuilt from disk on every open.
