# Architecture notes — Model, attributes, editable text widgets

Read from the real source; structural facts the rewrite must
reproduce for this area.

OWNERSHIP / DATA FLOW
- A Model is the Tracker-side identity of one filesystem entry: it owns an entry_ref (with a strdup'd name), a cached `struct stat`, a cached MIME type string, an `fBaseType` kind tag, an `fIconFrom` icon-source tag, and an optional *lazily opened* BNode*. `Model::NodeRef()` returns `(node_ref*)&fStatBuf` — it ALIASES the first two fields of the stat buffer. Any rewrite must keep device+inode as the leading two fields of the stat record, or every NodeRef() comparison breaks (Model.h, inline Model::NodeRef).
- One tagged union holds three different things discriminated by fBaseType: `fPreferredAppName` (normal), `fVolumeName` (kVolumeNode), `fLinkTo` (kLinkNode, an owned child Model). `Model::DeletePreferredAppVolumeNameLinkTo()` MUST be called before fBaseType changes or before overwriting the union, otherwise the wrong destructor path runs. Every `SetTo()` overload resets fIconFrom=kUnknownSource, fBaseType=kUnknownNode, fMimeType="" first.
- Node open state is a 3-state machine: closed / open read-only / open read-write. `OpenNode(writable)` is idempotent when the requested writability already holds, else it re-opens. `ModelNodeLazyOpener` (stack RAII, Model.h) records the prior state in its constructor and RESTORES it in its destructor — closing if it was closed, demoting to read-only if it was read-only. BModelOpener/BModelWriteOpener are the eager flavors. All attribute writes go through this so a Model that was closed stays closed.
- fBaseType is decided in two stages: `SetupBaseType()` from st_mode alone (cheap, no node open), then `FinishSettingUpType()` once the node is open — which is the only place that reads BEOS:TYPE and can *reclassify* a plain file into query / query template / virtual directory, a directory into trash / desktop, a directory into volume, a volume into root. `OpenNodeCommon()` calls SetupBaseType() if unknown, opens the right BNode subclass per kind (BFile / BDirectory / BSymLink), then calls FinishSettingUpType() only if fMimeType is still empty.
- WidgetAttributeText is a per-(model, column) text formatter, created by the factory `WidgetAttributeText::NewWidgetText()` which dispatches on `column->AttrName()` first and `column->DisplayAs()` second. It holds a NON-owning `Model* fModel` and `const BColumn* fColumn`; the column must outlive the widget. Two-level caching: `fValueDirty` guards the raw value (fFullValueText / fValue), `fDirty` guards the fitted/truncated string (fText). Reading is always lazy.
- BTextWidget (one per pose per column) owns exactly one WidgetAttributeText and caches `fAttrHash` (= AttrHashString(name,type)) and the column alignment/editability *at construction time*; column lookups later go through `poseView->ColumnFor(fAttrHash)`.
- Editing is a singleton per pose view: at most one BTextWidget is active. StartEdit builds a real BTextView named "WidgetTextView" inside a BScrollView named "BorderView" added as a child of the pose view; StopEdit finds them back BY NAME, commits, removes and deletes the scroll view. BPoseView::fActivePose + fActiveTextWidget track it; BPoseView::CommitActivePose() -> BPose::Commit() -> BTextWidget::StopEdit() is the single commit path, invoked from ~15 places (window deactivate, Escape/Return, Tab, click elsewhere, detach, sort change).
- View state is two archived objects: BColumn (one per column) and BViewState (one per folder), serialized either into a BMallocIO byte stream stored in a node attribute, or into a BMessage (used for file panels / state hand-off). Streams are self-describing: `AttrHashString("BColumn", B_OBJECT_TYPE)` + version int32 header.
- AttributeStream* is a pull pipeline built with `operator<<`, chained sink-to-source: `*destination << transformer << filter << source`. Each node has fReadFrom/fWriteTo; attaching a node auto-Start()s the chain, which walks to the head and calls Drive(), which Rewinds and pumps Next()/Get() pairs into the destination. Detach() tears down both directions recursively.

THREADING
- Models are constructed on the background `BPoseView::AddPosesTask` thread WITH THE WINDOW UNLOCKED, then handed to the pose view in chunks under the window lock. Node monitoring is started (`WatchNewNode`) BEFORE the Model is constructed, precisely because the Model caches file type and preferred app — otherwise a change between construction and watch is lost. That ordering is a real invariant.
- Everything else (widget formatting, editing, view-state save/restore) runs on the window thread. WidgetAttributeText is not thread-safe and assumes the window lock.
- Node-monitor attribute updates re-open the pose's model with up to 100 retries at 10 ms apart on B_BUSY, because mimeset may hold the node (BPoseView::AttributeChanged).

INVARIANTS
- fMimeType is never empty after a successful open: every fBaseType branch of FinishSettingUpType assigns a default.
- A symlink Model's fLinkTo is a separately opened Model; ResolveIfLink() returns `this` when unresolved, so callers never get NULL.
- Attribute identity for columns is `AttrHashString(name, type)`: a name hash whose low byte is REPLACED by the type code. Collisions are possible and acknowledged in the source; column lookup, widget lookup and sort keys all use this hash.
- Native/foreign endian attribute pairs: on a little-endian host the native names carry the "_le" suffix ("_trk/columns_le") and the unsuffixed name is the foreign one. Read tries native then foreign+swap; write writes native then DELETES the foreign twin so stale data cannot resurrect.
- Persisted column offsets/widths are divided by `be_plain_font->Size()/12` on write and multiplied back on read, so layout follows font size across sessions.
- Restored column offsets are always discarded and recomputed left-to-right in AddColumnList(); only widths and order survive.
- fStateNeedsSaving (pose view) OR BViewState::StateNeedsSaving() (field-by-field diff against a snapshot taken at load/save) gates writing state back; the write silently no-ops if the folder's node cannot be opened for writing.
