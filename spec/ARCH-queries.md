# Architecture notes — Queries and the Find window

Read from the real source; structural facts the rewrite must
reproduce for this area.

OWNERSHIP / DATA FLOW. FindWindow (a BWindow, own message thread) owns `fFile` (an open BFile on the query file) plus `fRef`; FindPanel (its BView child) holds ALL editable state in live UI widgets — there is no parsed in-memory query object. A predicate is regenerated from the widgets on demand (FindWindow::GetPredicateString -> FindPanel::GetByNamePredicate / GetByAttrPredicate, or the raw formula text). BQuery is used purely as a predicate *builder* (PushAttr/PushString/PushOp then GetPredicate) in the Find window; the actual searching BQuery objects live in the results window.

THE QUERY FILE IS THE ONLY PERSISTENCE UNIT, and it carries TWO parallel representations that are written together by FindWindow::SaveQueryAsAttributes + FindPanel::SaveWindowState: (a) the EXECUTABLE predicate string in `_trk/qrystr` (kAttrQueryString) which is all the results window reads, and (b) the EDITABLE UI state — `_trk/qryinitmode` (mode), `_trk/qryinitstr` (name/formula text), `_trk/qryinitnumattrs` + `_trk/qryinitattrs` (flattened BMessage of per-row menuSelection/subMenuSelection/attrViewText/logicalRelation), `_trk/qryinitmime` (MIME label) — which only the Find window reads. Plus `_trk/qryvol1` (flattened volume-identity message), `_trk/directories` (flattened refs of folder filters), `_trk/qrymoreoptions` (raw MoreOptionsStruct; a little/big-endian NAME PAIR, kAttrQueryMoreOptions/kAttrQueryMoreOptionsForeign, read via ReadAttr with an EndianSwap hook, with reserved fields so old queries stay readable), `_trk/queryDynamicDate`, `_trk/qrylastchange`, `_trk/recentQuery`=1, and `_trk/focusedView` + `_trk/focusedSelStart/End`. The file's MIME type (B_QUERY_MIMETYPE vs B_QUERY_TEMPLATE_MIMETYPE) is what makes it a query vs a template (Model::IsQuery/IsQueryTemplate, set from BNodeInfo type in Model::FinishSettingUpType). The two representations can diverge; only (a) affects results.

RUNNING A QUERY IS OUT-OF-PROCESS-STYLE INDIRECTION. FindWindow::Find does not display anything: it writes the file (FindSaveCommon) then posts B_REFS_RECEIVED with the query file's ref to be_app; TTracker::OpenRef sees Model::IsContainer() true for a query and opens a BQueryContainerWindow whose BQueryPoseView re-reads the predicate from the file. Re-running an existing query DELETES and recreates the file — that is deliberately how the old results window is forced to close (it node-monitors its own model); FindSaveCommon returns false in that case and Find then polls TTracker::EntryHasWindowOpen with 1 ms snoozes, bounded at 5000 iterations, before posting refs. This race and its bound must be reproduced or designed away.

RESULTS ITERATION. QueryEntryListCollection is an EntryListBase adapter owning ONE live BQuery per volume (QueryListRep::fQueryList); Rewind/GetNextEntry/GetNextRef/GetNextDirents walk queries in order via fQueryListIndex; CountEntries() returns 0 (count is unknown up front). Filtering is TWO-STAGE by design: path (folder) filters are applied inside the iterator so poses are never created for excluded nodes, AND again in QueryRefFilter::Filter so live arrivals are filtered too (comment in QueryEntryListCollection::PathFilter states this explicitly). The Trash filter lives only in QueryRefFilter. When path filters are active GetNextDirents is forced to count=1.

LIVENESS. Each BQuery gets SetTarget(poseView messenger) + SetFlags(B_QUERY_WATCH_ALL) in FetchOneQuery, so the kernel pushes B_QUERY_UPDATE into the pose view's looper; BPoseView::MessageReceived routes B_QUERY_UPDATE through FSNotification exactly like node-monitor B_ENTRY_CREATED/REMOVED, and query windows are explicitly allowed to receive entries whose parent dir differs from the target model. BQueryPoseView::WatchNewNodeMask() returns 0 because B_QUERY_WATCH_ALL already covers it — do not add per-node watches on top.

DYNAMIC DATES ARE APP-SCHEDULED, NOT KERNEL-DRIVEN. Nothing re-evaluates "today"; BQueryPoseView::InitDirentIterator computes the next midnight (or next hour / next minute) and posts a Refresh through TTracker::MainTaskLoop()->RunLater. Refresh clears fAddPosesThreads (killing the running AddPoses task), deletes the QueryEntryListCollection, sets fCreateOldPoseList, re-adds poses; the previous pose list is carried in QueryEntryListCollection::fOldPoseList and the leftovers are deleted in AddPosesCompleted (which asserts the window is locked). Pose adding runs on a separate thread; this teardown ordering is load-bearing.

THREADING. Each FindWindow is its own looper; MostUsedNames (the most-used MIME list) is a process-global guarded by a Benaphore with ObtainList/ReleaseList bracketing. DeleteTransientQueriesTask runs as an idle functor on TTracker's StandAloneTaskLoop in 100-entry batches.

SELF-REFERENTIAL BOOTSTRAP. The recent-queries and templates menus are themselves built by running a query (`_trk/recentQuery == 1`) on every persistent volume, which only works because TTracker::InstallIndices creates fs indices for `_trk/qrylastchange` and `_trk/recentQuery` on every writable volume at boot. BQuery is also documented (comment in FindWindow::PopulateTemplatesMenu) to return duplicate refs for deleted-and-recreated files, so both menu builders de-duplicate.

BUGS PRESENT IN THE ORIGINAL — DO NOT PORT: (1) FindWindow::MessageReceived case kOpenLoadQueryPanel has no `break`, so opening the Open panel also toggles "Include Trash"; (2) FindPanel::UserSpecifiedName() unconditionally returns NULL (the query-name text control was removed), so rename-on-save and the drag clip name always fall back to defaults; (3) DeleteTransientQueriesTask::QueryOldEnough compares tm_mday only, so "7 days" is really day-of-month arithmetic; (4) FindPanel::AddAttributes calls FindBool("attr:viewable") without an index, so it effectively tests attribute 0 for the whole type; (5) RestoreWindowState's "all volumes selected" branch marks item 0 then immediately unmarks it in the following loop, and the correct label is only recovered by ShowVolumeMenuLabel.
