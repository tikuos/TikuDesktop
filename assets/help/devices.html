Devices

A board reaches this desktop over a serial port, or by dialling in over the network when the desktop was started to listen for one. A connected board is mounted under /devices by its processor's name, so its files and settings open in a window like any other place here.

The Devices menu

The Devices menu sits at the right end of the menu bar across the top of the screen, after the menus of the window in front, and it stays there whatever window is focused. Its rows are these.

  • Default device names the device in use: Default device: This machine when no board is current, and the board's name in place of This machine when one is. Its submenu is titled Default device; the first row is This machine and the rest are the connected boards, each as its name and the port it answered on. The one in use is marked.
  • Connected devices is a heading, with one Disconnect row under it for each mounted board, naming it and its port. When none is mounted the heading is followed by No devices connected.
  • Available devices is a heading listing one Connect to row for each port that answered with a name and is not already mounted. A port that answers nothing is never offered, so the second port a debug probe puts up beside a board's console does not appear.
  • Scan for devices lists the ports again and asks each one that is not mounted for its name. A scan only lists. The board that answered is remembered under its processor's name, and its port is closed again.

Connecting and disconnecting

Connect to is the one row that mounts a board. It opens the port, and the board that answers is mounted under its processor's name. If nothing was current at the time, the board that lands becomes the current device; a second board joins it and does not take its place.

Disconnect unmounts the board and closes the port. It goes back onto the Available devices list under the name it already answered to, so a second scan is not needed to find it. If it was the current device, the desktop steps to another connected board, and falls back to this machine only when there is none.

The device tray

The menu bar keeps a small chip for each board at its right end, left of the camera. A chip appears as soon as Connect to is chosen: it fades in inside a ring that turns until the board answers, and the ring closes round it and fades as the board is mounted. With Reduce motion on, the chip waits dimmed inside a still ring and turns solid when the board is mounted.

  • A solid chip is a connected board. Resting the pointer on it names the board, its processor when that is another name, its port, and how long it has been connected.
  • A dimmed chip with an arrow is a board lent to another program, such as a test run that reflashes it. Its port stays closed until the board is asked back.
  • A red chip is a connect that nothing answered, a board whose link was lost, or a lent board that could not be found again. Its tip says which. It stays two seconds; a lent board's chip then goes back to dimmed, and any other goes.

A click on a connected board's chip drops a menu: Open its folder, Devices Preferences… on that board, and Disconnect. A lent board's menu has Reclaim, which asks every port for the board and mounts it again under its name. A double-click on a connected board's chip opens its folder. The chips never cover the menu titles; when there is no room for all of them, the ones that came last are left out.

The current device

The current device is where work goes when a window is not told otherwise; This machine means the desktop's own namespace. Every open application and every connected session is told when it changes. The choice is remembered by name and by port, and saved as soon as it is made. At the next start the desktop reconnects that one remembered port. It asks the other ports only for their names, so connecting a board stays something that is asked for.

A board's own windows

A board can publish forms of its own under gui. The first time the desktop sees them it opens each as a window titled by the form. A press on a button or switch row writes the change back to the board; a text row writes on Return, and a slider when the pointer is released. The board reporting a change under gui makes the open windows re-read. Four are held at once. A form with rows this build cannot draw says how many along the bottom.

Device Monitor

Device Monitor opens from Device Tools in the Deskbar menu. It captures the current device as it opens, and a later change of the current device never retargets it. Use default adopts the current device and Next device steps to the next connected board; either drops the readings already taken.

The monitor samples the board, then waits five seconds after each finished sample before asking again. Pause holds the last snapshot on screen; Resume and Refresh start it reading again. A reading the board does not publish is shown as Unavailable, never as a zero. Closing the window stops the polling.

Process RAM and store allocation each keep 120 samples of history, about ten minutes at that interval. Under the graphs the monitor lists up to eight processes, each as its number, name, state, SRAM bytes and queued events.

VFS Inspector

VFS Inspector also opens from Device Tools and takes its target the same way. On opening it reads the board's directory tree and the values it knows are safe to read, and shows /sys first, or / when there is no /sys.

The left pane is the tree, sorted by name; + and - or the Left and Right arrow keys open and close a branch. The right pane lists the selected directory in the columns Name, Type, Access and Data. Type an absolute path in the address field and press Go to path to jump, or Up for the parent. Refresh reads the tree and the safe values again.

A value the inspector will not read on its own says Manual read, one it did not reach within its scan limits says Not read, and a reading that failed says Unavailable. Click a value, or select it and press Return, to read that one endpoint. Copy value copies the whole of the accepted text even when the preview shows only its first lines. A value over 2046 bytes, or one that is not text, is refused.

Fewer endpoints can be edited here than the board marks writable. Five audited settings have an editor: /sys/device/name, /sys/cpu/freq_target, /sys/crypto/mode, /sys/radio/txpower and /sys/time. Everything else is read only here, command endpoints included. An edit is read, reviewed, then confirmed: Review edit shows the target, the path, the current value and the proposed one, Confirm save writes once and reads back, and Cancel edit changes nothing. A write is never retried on its own: a lost answer is reported as uncertain, and wants a Refresh before another try. A clock target must be one of the rates the board advertises, and no restart is automatic.

Both windows close with Done or with Escape.
