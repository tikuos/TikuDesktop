Developer Calculator

The Deskbar row is Developer Calculator, under Development. The calculator does not read a connected device. Everything it shows comes from the four fields in its own window.

It opens with the value field holding 0, the bit range set to 7 down to 0, and the checksum field holding 123456789. Input is read in base 16 and the word is 32 bits wide.

Words and radices

The first button reads Input: base 16 and names the radix the value field is read in. Each press moves to the next radix: 16, 10, 2, 8, and back to 16. The value is kept across the change and rewritten in the new radix. In base 16 a leading 0x is accepted, and in base 2 a leading 0b.

The second button reads 32-bit word. Each press doubles the width, from 8 to 16 to 32 to 64, and the press after 64 returns to 8. Narrowing to a width the current value does not fit is refused, and the status line at the foot of the window says Value does not fit N bits. Change the value before narrowing. Nothing is masked away.

Every value is an exact unsigned integer. There is no floating point and no signed reading, so a negative sign, a digit that does not belong to the radix, and a value past the selected width are all rejected. A rejected value is not rounded: the four views read Invalid or outside selected unsigned width until the field is corrected.

A valid value is shown in four views at once.

The bit grid

Below the views are 64 buttons, 16 to a row, highest bit first. Each is labelled with its bit index and that bit's current value, such as 31:1. Clicking one toggles that bit and the views follow. Bits outside the selected width are disabled, and so is the whole grid while the value is invalid.

Swap byte order reverses the bytes of the selected word only. The bit order inside each byte is unchanged. Nothing swaps by itself: the button is the only way it happens.

Taking a bit range

The High bit and Low fields take an inclusive range and the line beside them shows what it holds, in hex and in decimal. Both fields are read in decimal whatever the input radix is. The range must satisfy 0 <= low <= high < the word width; outside that, and also while the value field itself is invalid, the line reads Use 0 <= low <= high < word width. instead of showing a number.

Checksums

The checksum field is read either as literal UTF-8 text or as hexadecimal byte pairs. The button above the field reads CRC input: UTF-8 text or CRC input: Hex bytes for the reading in force, and pressing it changes the reading. Hex pairs may be separated by spaces or tabs, but a lone half-byte is an error and the line reads Invalid hex bytes: use pairs such as 00 FF 12. No newline and no terminator are added to what you typed.

The line below the field gives the byte count and both checksums. Both are computed over the same bytes.

The two values in the last column are the standard check values for those two checksums, and the field holds 123456789 when the window opens, so they are on screen at the start.

A field takes at most 255 bytes. Typed as hex pairs with no spaces between them, that is 127 bytes of data. Text past the limit is refused and the status line says so rather than taking part of it.

Copying, and closing

Copy conversions puts the four views on the desktop clipboard, one to a line. Copy checksums puts the byte count and both checksums there. Each says Copied to desktop clipboard. in the status line, or Clipboard unavailable. when there is no clipboard to write to. Neither button copies while what it would copy is invalid.

Tab and Shift+Tab step between the buttons, the fields and the bits. Done, the Escape key, and Close in the window's own Calculator menu all close the window. Ctrl+W does not. The calculator runs in a process of its own, so that chord goes to the calculator rather than to the desktop, and the calculator does not act on it.
