Descriptor Demo

The Descriptor Demo is an application built against the public SDK. Choose it from Demos, or run build/examples/tiku-demo-app against an existing desktop. Both routes run in a separate process, connected through ~/.config/tracker/desk.sock. The legacy TIKU_EMBED_DEMO switch also starts the separate application; it no longer links the demo into the desktop.

The same descriptor paints the window, publishes menus and receives events. The desktop supplies window and device services without exposing private state to the application.

What the window shows

The window is titled Descriptor Demo. It is 400 by 210 pixels and does not resize: the demo never asks its host for a window the person may resize.

On the left is the TikuOS mark, the word TikuOS under it, a short rule, and the words one descriptor.

On the right are three lines.

  • The heading The same descriptor, either way.
  • The kernel of the machine this is running on: its name, its release and its machine type, as uname reports them. When that call fails the line reads unknown kernel.
  • How long the machine has been up, read from /proc/uptime and written as up 3 days, 4:07. Once a minute the strip this line sits in is repainted. That strip runs from where the three lines start to the right edge of the window, and the repaint covers nothing above it or below it.

Along the foot is a line such as pid 4711: whose faults are whose. The process id is the demo's own, distinct from the desktop.

The Remote menu

The window publishes one menu, named Remote, and it reaches the bar at the top of the screen while the demo's window is in front. Out of process the menu crosses the socket as plain data first. It carries two rows.

  • Refresh paints the whole panel again. Anything drawn over it since it opened, including the marks below, is painted over.
  • Quit ends the application. The program exits and the desktop takes down the window whose session has gone. The Escape key does the same thing, and so does closing the window, which is the only window the demo opens.

The application names this page for itself when it starts, so the Tiku menu carries a Help… row while the demo's window is in front, and that row opens this page. The demo names it the same way from either host.

A drag leaves marks

Pressing the pointer over the panel, moving it and releasing it each stamp a small square where the pointer is. The press and the moves are drawn in the colour of a window tab and the release is drawn in the text colour, so the end of a drag can be told from the rest of it. A move with no button held reaches the window as well, so passing the pointer across the panel marks it too.

Most of the marks stay. The once-a-minute repaint covers the strip the uptime line sits in, so a mark that landed inside that strip is painted over when the minute changes, and a mark anywhere else is left alone. A drag across the window crosses that strip. Refresh clears every mark. Out of process, every one of those pointer events crossed the socket to the application and every mark came back as part of a frame. The marks a drag leaves are the same either way.
