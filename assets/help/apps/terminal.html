Terminal

Terminal runs the shell of the machine TikuDesktop itself is running on. It is opened from Utilities in the Deskbar leaf. It opens no serial port and reads no connected board: the shell in the window is this computer's. The console of a board is a different program, TikuConsole, under Device Tools.

The shell it runs

Opening the window starts one shell on a pseudo-terminal of its own. The program started is the one named by the SHELL variable; when that variable is unset or empty, or when the shell it names cannot be run, /bin/sh is started instead. The shell is started interactive, and the pseudo-terminal is its controlling terminal, so job control works in it. TERM is set to vt100 for it.

When no shell can be started at all, the screen says no shell could be started and the strip says the shell has exited. Nothing is sent and nothing is received. Clear and Reset still blank the screen, and Quit still ends Terminal.

The window

The screen is 80 columns by 24 rows. The window opens at that size and keeps it: Terminal does not ask the desktop for a window the person may resize, so the size does not change while it is open. The window is titled Terminal, and a title a program sends over the terminal is read and discarded rather than shown.

Under the screen is a strip of one line. While the shell is running it names the screen's size and the terminal being emulated, as 80x24 vt100. While the view is scrolled back it says how many lines back the view is, and once the shell has ended it says the shell has exited.

The screen draws the eight ANSI colours, bold and reverse video. The cursor is a block on the place the next character lands, drawn only while the shell is running and the live screen is being shown. The sequences understood are a VT100 subset: enough for a line editor, a pager and a full-screen editor.

Typing

Every key goes to the shell as the bytes a terminal sends for it.

KeyWhat the shell is sent
A printed characterthat character
Returna carriage return
Backspacethe delete code
Tab, Escapetab, escape
Arrows, Home, End, Delete, Page Up, Page Down the escape sequence a terminal sends for that key
Ctrl and a letter that letter's control code, so Ctrl+C sends code 3

Text committed by an input method is sent whole, so accented and non-Latin characters reach the shell as typed. Ctrl with a key that is not a letter sends nothing. Ctrl+W is taken by the desktop before Terminal is offered it; it is described under Closing it.

Looking back

Lines that scroll off the top of the screen are kept, 500 of them. A program that sets a scroll region scrolls inside it, and those lines are not kept. Shift+Page Up steps back through what is kept 23 lines at a time, one line short of a screen, so a line of the old screen stays in view; Shift+Page Down comes forward again. Neither is sent to the shell. While the view is back, the strip says how many lines back it is and that Shift+Page Down returns. Typing brings the view to the live screen first, so a keystroke never lands on a screen that is not being shown.

The Terminal menu

While its window is in front, Terminal puts one menu named Terminal on the bar at the top of the screen.

  • Clear blanks the screen and puts the cursor at the top left. The shell is not told, so its idea of the screen is unchanged. Lines already scrolled off stay in the scrollback, and the lines cleared off the screen are not added to it.
  • Reset puts the colours, the attributes, the scroll region, the parser and the cursor back as they were when the window opened, and blanks the screen. The shell is not ended. Use Reset when a program stopped mid-sequence and left the screen unreadable.
  • Quit ends Terminal, as closing its window does.

The Tiku menu carries a Help… row while Terminal's window is in front, and that row opens this page.

The clipboard

Terminal does not use the desktop's clipboard. It puts no text on it and takes none from it, so there is no copy out of the screen and no paste into the shell. Ctrl with a letter is sent on as that letter's control code, which is what Ctrl+V does as well. Clicking in the screen selects nothing: Terminal reads the keyboard only.

Closing it

Ctrl+W closes the window. The desktop closes it itself and never hands that chord to the program inside, so a Terminal is always closable from the keyboard. Terminal has one window, and closing it ends Terminal, which is also what Quit does. Either way the shell is sent a hangup and the pseudo-terminal is closed.

When the shell ends by itself, by exit or otherwise, the window stays open and the strip says the shell has exited. Nothing is started in its place, and keys are not sent. Close the window and open Terminal again for a new shell.

A board's shell

Terminal always runs a shell on this machine. The default device in the Devices menu does not change what it runs, and a board mounted on this desktop is not reachable from it. The shell of a connected board is reached with TikuConsole, which asks the desktop for the chosen board and holds that board's serial port from Open console until Return to desktop.
