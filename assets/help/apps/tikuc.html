TikuC

TikuC is TikuBasic built for C. One source makes both, so the project window, the editor windows, the Window menu, Find and Replace, and the recovery of unsaved files all work as TikuBasic describes them. This page says only what is different. The Deskbar leaf offers TikuC under Development, and its project window is titled Project.

What differs

A file's language comes from its name rather than from which of the two programs opened it: .c and .h are C, .bas is BASIC. TikuC differs only in which rows and tools it offers.

  • New Project… writes a project whose one file is main.c and opens it. New File… offers the name untitled.c.
  • A C page's toolbar is Save, Build, Undo, Redo and Find. The run arrow, the stop square and the renumber tool are drawn only on a BASIC page.
  • A C page's File menu holds only Save and Close. Its Edit menu ends at Toggle comment (Ctrl+/), which uses //: no Renumber, no Complete keyword, no Keyword help. There is no Debug menu.
  • On a C page Return keeps the line's indentation and adds a level after a line ending in {; a } typed at the start of a line goes back to the indentation of the line that opened it.
  • The Project menu offers no Run row, no Save on a board and no Stop. Nothing here runs a C program. The line under the toolbar still reads Run on: with a device name, because the editor window is the same one, but on a C page nothing uses it.
  • Build for is always on the Project menu. In TikuBasic that row appears only when the project says what it is for.
  • Checkpoints of changed, unsaved files are kept in ~/.TikuC-recovery.

Build

Build runs a compiler over the project's C and shows what the compiler printed. Every row of the project whose name ends in .c is passed to it, with the project's own folder on the include path and with -fsyntax-only, so nothing is written and nothing is linked. Making an image for a board needs a toolchain for that board. Build pressed on the toolbar saves the page first.

The target is the target line of the project description. A project that names none is built for host, which is this machine. These are the compilers TikuC looks for.

TargetCompiler
hostcc
rp2350, ambiq, nordic, stm32n6, ra8p1 arm-none-eabi-gcc
msp430msp430-elf-gcc

A target outside that table is refused with ? nothing here knows how to build for and its name. A project with no .c row in it is refused with ? this project has no C in it to build. A build that has not finished after thirty seconds is stopped.

What the compiler said

Everything the compiler printed goes to the Messages window, which comes forward once the build has ended. A build that printed nothing opens no window and leaves the screen as it was; a compiler that prints nothing has found nothing to report. A line that begins with a file name and a line number is remembered as a position in that file: select that row and the Message menu offers Go to line with the number, which opens that file, if it is not open already, and puts the caret on the line. For a row about nowhere the menu says This one is not about anywhere instead.

The open pages show the same problems where they are: the name at the column the compiler gave is underlined, with a wavy red line for an error, a wavy orange one for a warning and a straight blue one for a note, and what the compiler said appears in a band under the line. Next problem (Ctrl+') and Previous problem (Ctrl+Shift+') in the Edit menu select them in turn. The next build clears them.
