# Architecture notes — Icons, thumbnails, pose visuals

Read from the real source; structural facts the rewrite must
reproduce for this area.

TWO CACHES, LAZY LOCKING. IconCache (process-global singleton `IconCache::sIconCache`) owns a SharedIconCache (BOpenHashTable keyed by {mime type, app signature}, Init(256)) and a NodeIconCache (keyed by node_ref, Init(100)). Each is a SimpleIconCache with its own Benaphore. `IconCache::Draw`/`SyncDraw`/`IconHitTest` construct BOTH AutoLocks in the *unlocked* state, hand them to the private `IconCache::Preload`, which decides where the icon lives, locks only that one, and returns it through `resultingOpenCache`; the caller draws through `resultingCacheLocker->LockedItem()->Draw(...)` and the lock releases at scope exit. A rewrite must preserve "only one of the two caches is locked, and the finder chooses which".

ENTRY SHAPE. IconCacheEntry holds at most four bitmaps: fMiniIcon, fHighlightedMiniIcon, fLargeIcon, fHighlightedLargeIcon. `HaveIconBitmap` treats "mini" as the single size `IconCache::sMiniIconSize` (computed once in the IconCache ctor from be_control_look->ComposeIconSize(B_MINI_ICON)) and checks it only for non-NULL; any other size uses the "large" slot AND requires `fLargeIcon->Bounds().Size() == size` exactly. So one entry caches exactly one large size at a time — changing view icon size silently re-fetches and overwrites. `SetIcon` deletes the previous bitmap in the slot.

ALIASES. An entry may be an alias (fAliasTo -> a SharedCacheEntry); aliases own no bitmaps and every lookup calls ResolveIfAlias. Aliases are how negative results are memoised: a (type, preferredApp) pair that ends up on the generic icon is inserted as an alias to the generic entry (GetGenericIcon, GetIconFromFileTypes, GetIconFromMetaMime). NodeIconCache and SharedIconCache both need RemoveAliasesTo() before an aliased-to entry is retired.

SOURCE MEMOISATION. Model stores fIconFrom (IconSource enum). First lookup runs the full search and calls model->SetIconFrom(source); later lookups take a switch shortcut on that source. Any total miss calls `model->SetIconFrom(kUnknownSource)` to force a full re-search next time. Model::FinishSettingUpType pre-seeds it (kUnknownNotFromNode when CheckAppIconHint fails, kNode when a thumbnail attr exists or the type is thumbnailable, kTrackerSupplied for well-known dirs, kVolume for volumes).

POST-CONDITION INVARIANT. `Preload` asserts on exit `entry != NULL && entry->HaveIconBitmap(mode, size)`. Two guaranteed backstops make that true: GetGenericIcon (B_FILE_MIMETYPE from the MIME db) and then GetFallbackIcon (R_FileIcon straight out of Tracker's own resources). A rewrite must keep a resource-baked last-resort icon that cannot fail.

BITMAP OWNERSHIP. LazyBitmapAllocator allocates one working BBitmap of the requested size/colorspace (kDefaultIconDepth = B_RGBA32) per lookup; `Get()` borrows, `Adopt()` transfers ownership to the cache entry. Because the shared cache may have handed a bitmap to DrawBitmapAsync, icons are NEVER deleted inline: `IconCacheEntry::RetireIcons` moves them to SharedIconCache::fRetiredBitmaps and only when that list exceeds 10*1024 are the oldest 512 deleted.

DRAW MODES. SharedCacheEntry::Draw honours the async flag (DrawBitmapAsync); NodeCacheEntry::Draw deliberately never draws async (`if (false && async)`) because node bitmaps can be freed. Both pick B_OP_ALPHA/B_PIXEL_ALPHA/B_ALPHA_OVERLAY for B_RGBA32 and B_OP_OVER otherwise, and restore the view's previous drawing_mode.

THREADING FOR THUMBNAILS. Up to two detached worker threads (`thumbnail_worker` over BSupportKit JobQueue), one for files < 128 KB and one for >= 128 KB, created lazily. GenerateThumbnailJob::Execute runs OFF the window thread: it translates the file to a BBitmap, scales it, and inserts the result directly into the node icon cache under `AutoLocker<NodeIconCache>`, then writes attributes, then (only if the attribute write failed) posts kUpdateThumbnail to be_app. A static std::list<GenerateThumbnailJob*> guarded by its own BLocker provides per-node dedup. Any rewrite needs the same "worker mutates the cache under the cache lock, UI is told to repaint afterwards" split.

DRAW OWNERSHIP SPLIT. BPose::Draw sets ONLY the low color (and the cut-item alpha state); BTextWidget::Draw sets the high color and drawing mode. BPose draws the icon via the cache, the label via BTextWidget -> WidgetAttributeText::FittingText. The selection inversion of the label happens in BPose::DrawTextWidget *after* the widget drew itself. BPoseView::MakeDragBitmap re-enters BPose::Draw with a foreign drawView and an offset, so every draw path must accept (drawView != poseView) and an offset.

GEOMETRY. Pose locations are stored unscaled against a 32 px reference: `Location()` multiplies fLocation by scale = IconSizeInt()/32 in kIconMode, `SetLocation`/`MoveTo` divide. IconSizeInt() = be_control_look->ComposeIconSize(viewState icon size).IntegerWidth()+1, so every size is font-scaled. `icon_size_for(BSize)` = IntegerWidth()+1 and asserts square icons.

CHANGE PROPAGATION. Two distinct invalidation paths: (a) per-node — node monitor B_ATTR_CHANGED/B_STAT_CHANGED -> Model::AttrChanged/IconAttrChanged -> BPose::UpdateIcon -> IconCache::IconChanged(Model*) which drops the node-cache entry and calls Model::ResetIconFrom(); (b) per-type — B_META_MIME_CHANGED -> BPoseView::NoticeMetaMimeChanged -> accumulated 200 ms (max 5 s) -> BPoseView::MetaMimeChanged -> IconCache::IconChanged(type, app) which removes aliases in both caches and retires the entry, then re-icons every pose whose MimeType matches and whose icon did not come from the node.
