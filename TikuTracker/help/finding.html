Finding things

Find searches the namespace and opens a window of results. Select picks items out of a window already open. Both belong to TikuDesktop: the single-window TikuTracker front-end has no Select window, and asking it to Find puts a line in its status bar saying the command is not available in that shell.

The Find window

It opens with Ctrl+F, from Find… in a window's File menu, from Find… in the Deskbar leaf, or from Find… in the Tiku menu. Only one is ever open: a second request brings that window forward. Return presses the default button, Escape closes the window.

The control at the top, labelled Find, chooses between by name, by attribute and by formula. The window opens on by name.

By name

One field, labelled Name contains. A star anywhere in the text makes the whole text a pattern, so *.txt and a*b are matched against the whole name; text with no star is matched as a substring. Case is folded, and a space matches any run of characters, so foo bar also finds foo-bar. Empty text matches everything.

Ctrl+Space in this field completes what is typed against the first place the search is scoped to, or against the home folder when the search is everywhere.

By attribute

Rows, each of them a field, an operator and a value. + adds a row and - removes the last one; there are at most four, and the remove button is disabled rather than hidden while one row is left. Between a row and the next sits and or or. Rows fold strictly left to right with no precedence, so a or b and c means (a or b) and c.

The field menu always offers Name, Size and Modified. Path, Kind, Value, Unit and Capability appear only once a type is chosen in Of type, and only where that type declares them. A field offers just the operators that suit it: text fields offer contains, is, is not, starts with and ends with; Size offers is, greater than and less than; Modified offers after and before. A Modified value is written as now, today, yesterday, 3 days ago, 2 hours from now, or a date such as 2026-09-13.

By formula

One field, labelled Formula, holding the predicate itself. Switching into this mode fills the field with the predicate the controls were asking. Switching back out keeps the attribute rows as they were.

(name=="[tT][xX][tT]")&&(size>100)

A term is a field name, one of ==, !=, > or <, and a value, in brackets; a quoted value is used as a pattern exactly as written. Terms join with && and ||. The field names are name, path, kind, value, size, cap, unit, writable, type and modified. A formula that does not parse runs nothing, and the status line says the formula is invalid. Of type is not shown in this mode, because the formula is the whole question.

Type, scope and Trash

Of type narrows every term to one type. Its menu leads with All files and folders, then the four types chosen most recently, then a submenu per family headed by All and the family name. Choosing a family admits everything under it.

Search in says where to look: Everywhere, then the top-level places the desktop read when it started, at most eight of them, and last Select folders…, which opens a file panel and scopes the search to the folder chosen there at once. The button shows the one place, the number of places, or Everywhere. Include Trash is off unless it is ticked.

The results

A search opens its own window, titled find # and a number, and the status line reports how many results came back and where from. The window is live: it re-runs about every three seconds while it is open, keeps the items that still match, and says what came in and went out.

Ctrl+G, or Edit query in the File menu, re-opens the Find window filled in with that search instead of running it again. If one of its places is no longer here, the status line says so rather than searching somewhere else.

Saved searches

A saved search is a record the desktop keeps under a name, in one of two kinds. Choosing either from the Queries menu fills the Find window in, ready to be changed; neither is run by being chosen. The difference is what Save does: it writes back into a loaded query, and running that search again replaces its record rather than leaving a second one, but it refuses a loaded template unless the window is the one editing that template in place. Every search that is run leaves a record behind, and one never given a name of its own is marked temporary and swept away after seven days.

The Queries button opens a menu holding Save as template, then the templates, then the searches that were run, newest first and at most ten of them, and last Edit loaded template when a template is loaded and is not already being edited in place. Choosing a name loads that record into the window.

The Save button writes back to the record the window came from. With nothing attached it asks where instead, through the Save panel: the search is written as a file at the place chosen, and the same record is kept under that file's name so the Queries menu knows it too.

The small query icon in the window can be dragged. Dropped on a folder or on the desktop it offers Create a Query and Create a Query template, which save the search there under the name New Query; both rows are disabled where nothing can be written. There is no icon while the title reads Edit Query template.

The Select window

Ctrl+Shift+A opens it near the pointer, and Select… in the Window menu opens the same window. It belongs to the window it was opened from and changes the selection there; it hides nothing.

The label reads Select items whose name, and beneath it are the expression, the rule, Ignore case, Invert selection and the Select button. Clicking the rule, or pressing Tab, steps to the next one.

RuleWhat it matches
starts withnames beginning with the expression
ends withnames ending with it
containsnames holding it anywhere
matches wildcard expressionthe whole name, with *, ? and character classes
matches regular expressionthe expression anywhere in the name; ^ and $ anchor it

It opens on the wildcard rule with Ignore case ticked, so an expression with no wildcards in it is an exact, case-blind match. Return selects and Escape closes. Selecting replaces whatever was selected in that window, and the status line says how many items were picked; with Invert selection ticked the items that do not match are the ones picked. A regular expression that does not compile is refused in an alert, and nothing is selected. Closing the window hides it rather than emptying it, so the expression, the rule and the two boxes are still there next time.
