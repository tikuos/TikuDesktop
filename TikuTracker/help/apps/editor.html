Editor

The Deskbar row Editor, under Applications, starts a plain text editor. The window opens at 560 by 400 pixels. Opened with no file, it is titled Edit, which is the program's own name.

Along the foot of the window is one line of small text: a * while there are changes nothing has saved, the file the document came from or untitled, the line and column the caret is in, and the editor's last message.

What it opens

Started from the Deskbar, the editor opens with nothing in it: the foot line says untitled and new file.

The Deskbar row starts the loadable copy of the editor, which takes no file name. The separate tiku-edit program takes one when it is started, and that is how a document reaches it when an applications entry naming that program opens one. It reads the file whole, breaks it at the line ends, titles the window with the last part of the path, and says how many lines it read. A name that is nowhere on disk is not refused: the document opens empty and the foot line says new file.

The name also decides the colouring, once, before anything is drawn: .bas opens coloured as BASIC, .c and .h as C, every other name as plain text.

Open… on the File menu asks the desktop for its file panel, starting in the folder the open document lives in, or where the shell would open it when the document has no name yet. The panel answers later, and a panel closed without choosing answers not at all. When it does answer, the editor reads the name for the colouring again and loads the file over what was in the window.

How it saves

Save writes every line of the window to the file the document was opened as, each line followed by a line end, so a saved file ends with one. The foot line then says how many lines were written. The write counts as done only when the file is closed, which is where a full disk shows up: the close fails, the foot line says could not finish writing, and the document stays marked as changed. A file that cannot be opened for writing is reported as cannot write and the path.

A document with no name has nowhere to save. Save says no file name to save to and writes nothing; Save as… is the row that gives it a name. Saving-as takes the name first and writes after, so a write that fails leaves the document pointing at the name it was given.

The File menu

The editor publishes one menu, File, drawn on the bar across the top of the screen while an Editor window is in front.

  • Save writes the document. It is offered greyed while there is nothing to save.
  • Revert reads the file again and the changes go, and is greyed the same way. A document with no name has no file to read, and reverting it leaves the window empty.
  • Quit ends the program at once. It does not ask, and unsaved changes go with it.
  • Colour as BASIC turns the colouring on and off, and shows a mark while it is on. What it turns on is BASIC, whatever the file is named.
  • Run runs the document. It is offered greyed unless the document is being coloured as BASIC and no run is going.
  • Open… and Save as… ask the desktop for its file panel.

The keys

A printable character is inserted at the caret. Text from a compose key or an input method is inserted in one piece; one that does not fit is refused and the foot line says so.

KeyWhat it does
Left, RightOne character, and across a line end into the line before or after
Up, DownOne line, keeping the column where the line reached is long enough
Home, EndThe start and the end of the line
Page Up, Page DownA screenful of lines, keeping the column
ReturnBreaks the line at the caret
BackspaceThe character before the caret; at the head of a line, joins it to the line above
DelThe character under the caret; at the end of a line, joins the next line to it
Ctrl+SSaves
EscapeCloses the window, asking first when there are unsaved changes

Ctrl+S is the only chord the editor answers; Ctrl held with any other key does nothing here. The view follows the caret, and the pointer moves nothing in the text.

Closing

Escape on a document with no changes closes the window. On one with changes it opens a question over the text instead: Discard unsaved changes? Cancel keeps the window and Discard closes it, losing what was typed. Escape presses Cancel and Return presses Discard. The question offers no Save, so save before closing.

Running a BASIC program

Run writes the document to its file first, so what runs is the file and not a copy that existed only in the window; a document with no name is written to /tmp/tiku_edit_run.bas and run from there. It is handed to tiku-basic, the same interpreter a board runs, together with the folder the file is in, which is where the program's own files are written.

What the program prints appears in a pane at the foot of the window, newest last, and the text area shrinks by the height of the pane. The pane keeps the last 48 lines and shows seven. The foot line says running while the run lasts, then finished when the program ended cleanly and stopped when it did not. Once a run has printed, the pane stays for the rest of the session.

The interpreter is looked for by name, so it has to be on the path; the TIKU_BASIC variable names another one. When there is none, the pane says it could not run it and the foot line says stopped.

What the window holds

The editor reads the first 31999 bytes of a file, keeps at most 4000 lines, and cuts a line longer than 1023 characters. Saving writes what the window holds, so anything the reading left behind is not written back.
