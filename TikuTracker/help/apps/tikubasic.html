TikuBasic

TikuBasic is where a BASIC program is written, run and kept. The Deskbar leaf offers it under Programming. TikuC is the same application built for C: the same windows and the same way of working, putting Build forward where this one puts Run. See TikuC.

With one of its windows in front, Help… in the Tiku menu on the top bar opens this page.

The project window and the editor

In Tracker, double-click a local project.tiku (or another .tiku project description) to load its project in TikuBasic. Double-click .bas to open that source file for editing, without loading a project or running the program. Uppercase extensions work too. Open with → TikuBasic offers the same operation, while an explicitly chosen preferred handler overrides the default.

Each Tracker launch starts a separate TikuBasic session, leaving existing unsaved windows untouched. Starting from the Deskbar without a file still shows an empty project. Standalone TikuTracker needs TikuDesktop running to open these files; save device files locally first.

Starting the application shows its announcement for a moment, and then a window named Project. A project is a folder: New Project… makes a folder of the name given, holding the project description and the program's first source file. The list in the window is the files that description names. A group line in the description becomes a heading row among them.

The Project menu holds New Project…, Open Project…, Recover unsaved files, the run and save rows described below, Stop while a program is running, Build for the target the project names, and Close Project. About TikuBasic is not among them: the desktop takes that row and puts it in the Tiku menu on the top bar, beside Help…. The File menu holds New File…, Open File…, Add File… and Remove File, which takes a row out of the project description and leaves the file on the disk.

Opening a row opens an editor window of its own, named after the file. A file already open is raised rather than opened twice, and two editor windows fit at once; asking for a third says there is no room for another window. The Window menu, which the project window and every editor carries, lists the editors open now, and one holding unsaved work has (changed) beside its name.

The editor's toolbar for a BASIC file is Save, Run, Stop, Undo, Redo, Find and Renumber. A C file's toolbar is Save, Build, Undo, Redo and Find: Stop and Renumber belong to BASIC. A new BASIC file opens with line 10 already typed. Renumber counts the numbered lines by tens again and rewrites every branch to follow, as one undoable change.

Where a program runs

The line under the editor's toolbar says where the next run goes. It reads Run on: with the name of the device and then Ready or Disconnected. With no default device set the whole line is Run on: This computer — no default device. While a program is running the same line says so, and names what it is running on.

The destination is the desktop's default device, chosen in the Devices menu on the top bar; see Devices. A default that is named but not connected is never quietly replaced with a run on this machine.

A run on a board opens a console window named for the file and the board, holding what the program printed and the errors with the line numbers the interpreter gave them. A run on this machine puts what the program printed in the Messages window instead, and is stopped if it has not finished within thirty seconds. A program that asks for a line asks in the window its output is going to, and Return sends what was typed.

Run saves the file first

Run saves a changed file before anything is sent anywhere. A save that fails stops the run, and the note line says the source could not be saved.

The saved file is then read whole. Three things are refused before any of it reaches a board, so a part of a program is never sent:

  • more than 8191 bytes, which is Upload too large (maximum 8191 bytes)
  • a NUL byte anywhere in the file
  • a file that could not be read

A board's firmware has limits of its own and can refuse a program that passes all three.

Save on a board

Save on the board, in the Project menu, keeps the selected file on the board rather than running it. The row is there only while the desktop has a default device. A modified editor is saved first, as for a run.

The name on the board is the file's name without its extension, cut to the seven characters this interface takes, and it must be letters, digits or underscore; another name is refused and the file has to be renamed. The board holds the program as /data/<name>.bas.

Saving always asks first, because nothing here can ask the board whether that name is already taken. The question names the path, the board and the byte count, and says when the name was shortened to seven characters. Cancel is the button chosen by default; Save / Replace sends it. What goes is the board and the program as they were when the question was put, whether or not either has changed since.

Find and Replace

Edit > Find… (Ctrl+F) and Edit > Find and Replace… (Ctrl+H) open the bar under the toolbar, as does the Find tool. In a BASIC file, Find on its own labels the field Find / line:: a query of digits alone goes to the line with that number, and falls back to a literal search when no line has it. Find and Replace does not do this. Otherwise a search is literal and case-sensitive and does not cross a line end. The buttons are Next, Replace, All and Close; Tab changes field, Return finds the next match, or replaces the selected one when the caret is in the replacement field, and Escape closes the bar.

Replace changes the selected match, so a first press selects one. All replaces every match in the file as a single undoable change. An empty replacement deletes what was found. A replacement that would leave a line longer than 1023 bytes is refused whole and nothing in the file changes.

Edit > Find in project looks for the Find field's text through every file the project names, reading an open editor's unsaved text where there is one. Every line that holds the text becomes a row in the Messages window, at most 200 of them, and the editor says how many matching lines were found and how many files could not be read. It does not replace across files, and it is not offered while a program is running.

The Messages window

The Messages window is made when there is first something to put in it, and holds what a run on this machine printed, what a build said, and the results of Find in project. Its strip says running… or the run has finished.

A row that names a line carries Go to line and that number in the window's Message menu, and Return does the same: the file's editor opens if it is not open already, the caret goes to that line, and the window comes forward. A row that names no line reads This one is not about anywhere and cannot be followed.

Errors from a run on a board are in that run's console with their line numbers. Messages is used for them only when there is no console to hold them.
